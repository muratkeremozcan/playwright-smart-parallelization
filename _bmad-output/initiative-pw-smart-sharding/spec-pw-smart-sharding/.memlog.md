- (direction) Source: inputs/playwright-smart-sharding-comparison-and-handoff.md (web agent research 2026-10-15). Murat asked to plan with BMAD, then build with local agents.
- (decision) Aim for Gleb-style Playwright workflow convenience; reuse an existing balancing engine where it passes compatibility tests; build only the missing integration. No new scheduler assumed.
- (decision) Candidate engines: @flakiness/playwright (Playwright 1.62+, setup-aware SALT allocator, heavier reporter) and @nsxbet/playwright-orchestrator (Playwright 1.56+, JSON timings, Actions, serial/dependency behavior unverified).
- (decision) Allocation is static and preassigned from historical durations. Nothing in scope redistributes work mid-run. Live queues (Currents, rostmanrk) only if static planning is shown insufficient.
- (capability) CAP-1 Qualify each candidate engine on a published-package consumer fixture (semantic, failure-path, privacy, artifact-completeness proofs).
- (capability) CAP-2 Measure each qualified engine against native sharding on one representative real suite with matched paired runs.
- (capability) CAP-3 Produce a decision record: adopt, reject with reproduced reason, or inconclusive; names exact versions and the smallest remaining integration gap.
- (capability) CAP-4 Reusable Gleb-style CI workflow around the selected engine: prepare, matrix execute, artifacts, aggregate, history update, one-switch rollback. Built only after CAP-3 selects an engine.
- (capability) CAP-5 Trusted timing-history management: single writer, versioned and fingerprinted, bounded window, never overwritten by partial, zero-valued, or older data.
- (capability) CAP-6 Private-by-default operation: timings, test identities, and reports stay in private storage; no unwanted outbound connections; read-only PR runs.
- (capability) CAP-7 Fallback minimal Playwright Utils implementation via public Reporter.preprocess/TestRun API, only if neither engine qualifies and the failing fixture or measured cost is documented.
- (constraint) No speedup by skipping work: no fewer tests, dropped browser projects, changed retries, enabled fullyParallel, or larger runners.
- (constraint) Serial groups, setup/teardown dependencies, filters, and project selection must mean the same before and after adoption. File affinity never substitutes for serial correctness.
- (constraint) All shards in a run use one commit, config, selection, and immutable timing snapshot or assignment. Fallback to native sharding is chosen for the whole run before fan-out, or the run fails before execution.
- (constraint) Missing or corrupt shard artifacts or timing input never produce a green or silently partial result.
- (constraint) No undocumented deep imports (Flakiness exports the reporter only) and no patching of Playwright internals.
- (constraint) Do not mix durations across browsers, runner classes, worker counts, or materially different environments without justified normalization.
- (constraint) Timing data stays in the private repo or approved private CI storage. No public or unlisted gist. PR code from untrusted sources gets no write credentials.
- (constraint) Flakiness offline is not timing-only: disableUpload suppresses upload but report generation, source/attachment collection, and CPU/RAM sampling remain. Verify network behavior in the fixture.
- (constraint) Do not transplant the cypress-split pairwise-averaging timing merger; it is order-dependent for 3+ observations. Define a bounded observation window and review adaptation after tests speed up.
- (decision) Pilot gate: 5 matched alternating-order pairs; worthwhile gain predeclared at >=10% median completion-time reduction, no correctness regression, no material retry increase. Variability comparable to the gain means inconclusive.
- (decision) Compare completion time, per-shard durations, aggregate runner time, setup/report overhead, retries, history hit rate; separate queue delay from execution.
- (decision) Changed-specs-first prioritization (Gleb quick-changed-specs) is excluded from the first change so selection and scheduling effects stay separable.
- (decision) Proposed workflow inputs: working directory, config path, projects/filters, shard count, workers, timing artifact location, retention, engine enable switch. Names are proposals, not existing interfaces.
- (assumption) Target suite is the couture-cast Playwright suite. Reusable workflow ships through Playwright Utils or a standalone repo.
- (assumption) The 12.5 minute figure in the 10/15 example is an ideal bound, not a promise.
