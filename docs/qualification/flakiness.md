# Flakiness playwright reporter qualification

Verdict: qualifies with named gaps.

`@flakiness/playwright` keeps Playwright's native `--shard=i/n` and adds a reporter. In every shard the reporter reads a local timings file, packs the units Playwright itself shards by into balanced groups, excludes the tests of the other shards and switches the native split off. Because the units are Playwright's own, the engine keeps serial groups whole, runs setup and teardown where a shard needs them, honors filters and project selection, and covers every leaf once with and without history, under `--repeat-each` and under `fullyParallel` (proofs 1 to 4 pass, and so does the damaged shard file of case X1). It has four kinds of gap, each reproduced below. The shards do not check that they planned from the same input, and a command line that replaces the reporters turns balancing off without a word (proof 5). The first run fails when `shardBalancing` names a timings file that does not exist yet (proof 7). The `build` command accepts fewer shard reports than ran (proof 6). The history it builds keeps the longest duration it has seen, so one slow failed run raises an entry for good and a faster test never lowers it, except that a test stored once for two equally slow projects loses the price of one of them to a short run, and two runs racing to publish lose updates (proof 8 and case X2). The network audit finds no outbound connection with `disableUpload: true`, and the footprint is small.

The verdict follows a rule: an engine that fails proof 1 or proof 2, the exactly-once and serial semantics of Playwright sharding itself, does not qualify; an engine that passes both and fails another proof qualifies with named gaps, which the section on the smallest remaining integration gap names; an engine that passes every proof qualifies. A test derives the verdict from the proof results.

The rows below come from `npm run qualify:flakiness`. The tests in `qualification/flakiness/tests` assert every result in this document, and `tests/unit/docs.test.js` fails when the verdict, a proof result, a row result, a generated table or a number in a finding disagrees with the evidence. The [comparison with NSXBet](comparison.md) is built from the evidence of both engines.

## How the engine was driven

Every run goes through the S2 harness. The partition of a run is the native `--shard=i/n` of every shard. The config of the run (`qualification/flakiness/config.js`) adds the reporter the way the package README describes: `disableUpload: true`, no token, no project binding, and `shardBalancing: { timingsFile }` pointing at a local file. The timings file is built with `build` from the Flakiness reports of a native two-shard run with one worker per shard, and its durations are rounded to fifty milliseconds, so the plan does not depend on run-to-run noise. The balance runs use one worker per shard and the other runs use four.

| Flow     | What it does                                                                                   |
| -------- | ---------------------------------------------------------------------------------------------- |
| balanced | `--shard=i/n` on every shard with the reporter and a timings file built from earlier reports.  |
| cold     | The reporter with a valid timings file that knows no test, or with no `shardBalancing` option. |
| plain    | No reporter: Playwright's native sharding, the baseline of the balance and footprint tables.   |

## How the assignment is applied

The package source and the runs agree on one mechanism. Playwright calls `Reporter.preprocess` before the first test with the whole unsharded corpus. The reporter maps each test to its recorded duration through the Flakiness test id (file, titles) and the project name, prices a test it does not know at one second, packs the units of sharding into the shards, calls `testRun.exclude` for every test that belongs to another shard and calls `testRun.skipSharding()`. Row `4.applied-by-reporter` shows it by execution: the balanced split of a shard differs from the native split of the same shard, and with the reporter present and no timings file the split equals plain native sharding.

- A unit is the one Playwright shards by: a whole file by default, a single test under `fullyParallel`, and a serial suite as one unit under either. Setup and teardown projects are not units. The allocator prices their cost into the shards that need them and tries to keep the tests that share a setup on few shards. Rows `2.setup-aware` and `2.fully-parallel` show both.
- Each shard plans for itself, from its own copy of the timings file. The planner is a deterministic greedy pass with no time budget (`4.deterministic-plan`). Nothing in the engine compares the plan of one shard with the plan of another.
- Errors in the plan are fatal on purpose: a shard that cannot read its timings file fails before any test, so that no shard silently falls back to the native split (`5.truncated`, `x1.damaged-shard-timings`). The reporter reads the commit through git before it plans, so every shard needs a repository with a commit (`5.no-git-repository`).
- The reporter builds its report in `onEnd` and uploads in `onExit` unless `disableUpload` is set. On a Playwright older than the floor, the package source falls back to the native split with a warning; the fixture floats to the latest Playwright, so this path was read and not run.

## Where Flakiness answers differently from NSXBet

[The comparison](comparison.md) lists every row on which the two engines end differently. The differences follow from where each engine plans. NSXBet plans once, outside Playwright, over single tests, and hands each shard a `--test-list`. It splits serial groups, cannot tell one test in two projects apart, and runs a test in two shards when a list line selects more than one test. Flakiness plans inside every shard over the units Playwright shards by, so none of those rows fail. A damaged timings file on one shard fails that shard before any test, where NSXBet plans from estimates, and a damaged history file stops `build` and leaves the file as it was, where NSXBet's merge writes a file without the history. In the failed and cancelled runs measured, the history does not lower an entry, because the merge keeps the longest duration, where NSXBet's moving average pulls the entry down; a test stored once for two equally slow projects is the exception (`8.equal-durations`). The price of planning in every shard is that no step checks the shards against each other, which NSXBet's single planning step avoids (`5.mismatched-timings`, `5.reporter-dropped`), and that the maximum rule raises an entry for good (`8.failed-run-slow`, `8.faster-test`, `8.equal-durations`). Both engines accept a missing shard artifact when history is built, and in both two racing publishes lose updates.

## Privacy

The reporter makes no outbound connection with `disableUpload: true`. Two independent checks cover it. A preload (`qualification/lib/net-guard.js`) records and refuses every socket, DNS lookup and `fetch` in the process and its Node children, and records every process the reporter starts; its control row shows it catches each kind, the upload control row shows it catches the reporter's own upload once the flag is left off, and the mutation control row shows a started `curl` fails the check. The run carries a token and a vendor endpoint in its environment, so any upload attempt would reach for that host. The same run and `build` also ran under an OS-level network block, after the block was shown to stop a connection to a local listener. The audit is the empty log next to the control that fills it.

## Smallest remaining integration gap

The Action needs five pieces around the engine.

1. A cross-shard guard. Lock one timings file for the whole run, distribute that file to every shard, and fail the run when the plan lines the shards print differ or a shard prints none. Rows `5.mismatched-timings` and `5.reporter-dropped` reproduce the failures, and the first shows the plan lines differ when the files do. The same check catches a command line that replaces the reporters on every shard (`5.reporter-overridden`), and a Playwright older than the floor, which prints a warning and no plan. The check also reads the hint ratio of the plan and fails the run below a threshold, because a stale or empty timings file gives a run balanced on estimates with exit code 0 (`5.null-tests`, `5.stale-ids`, `5.zero-durations`).
2. A completeness check before history is built: count the shard reports that arrived against the shards that ran, and refuse to build with fewer (`6.missing-shard-report`, and `6.missing-blob` for Playwright's own merge).
3. A history policy. Keep the reports of a window of recent complete passing runs and rebuild the timings file from the window on every update, with no earlier timings file as input. Row `8.window-rebuild` shows that such a window adapts to a faster test once the slow run leaves it and leaves a failed run out, which the maximum over all history cannot (`8.failed-run-slow`, `8.faster-test`). The maximum still holds an entry at the slowest passing run inside the window, so the window length is the time an outlier lasts. A window also never merges an earlier timings file, which is what exposes `8.equal-durations`.
4. One trusted writer that records the run, commit and time next to the file and rejects an older run, because the file names no run (`x2.racing-publish`).
5. Cold start with a valid empty timings file, since a missing file fails every shard (`7.missing-timings-file`, `7.cold`), and a checkout with a commit in every shard (`5.no-git-repository`).

## Reproduce

```sh
npm run qualify:install
npm run qualify:flakiness
npm run qualify:flakiness:test
```

`qualify:flakiness` writes `qualification/flakiness/evidence.json`; `--group coverage|serial|balance|assignment|history|privacy` collects one group, and `--merge FILE...` joins the evidence of the groups. The `Qualification` workflow runs the six groups on separate runners and merges them before asserting. `qualify:flakiness:test` asserts every result; with `PSP_FLK_EVIDENCE=FILE` it reads an evidence file and skips the collection. The reference evidence behind this document is `docs/qualification/flakiness-evidence.json`.
